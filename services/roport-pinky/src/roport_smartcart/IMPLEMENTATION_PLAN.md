이 계획의 최신 업무 흐름은 11월 2일 강지원 요청을 따른다. 구현 상태와 검증 결과는 README에서 별도로 관리한다.

## 1. 이번 시연의 업무 범위

라인으로 상차 장소 이동 → 상차 확인 → 적재한 채 대기 장소 복귀 → 관제 배송 호출 대기 → Nav2로 지정 장소 배송 → 하차 확인 → 복귀.

QR·고객 마커 추종·쇼핑·HMI는 이번 구현에 포함하지 않는다. 팀 전체 요구에서 삭제됐다는 뜻은 아니다.
목적지 도착과 실제 짐 수령은 다른 사건이다. 하차 확인·관제의 복귀 허가 전에는 자동 복귀하지 않는다.
이 계획의 `unload_confirmed` 입력은 하차 확인과 복귀 허가를 모두 확인한 어댑터만 전달한다.

[TS-3 v5](https://fp-team1.atlassian.net/wiki/spaces/MFS/pages/11960332)는 P7 상차 후 즉시 배송·QR 인증 흐름이다.
상차 뒤 대기 복귀·호출 단계가 달라, 관제 어댑터를 연결하기 전에 계약을 맞춰야 한다.
기존 [FFT1-86](https://fp-team1.atlassian.net/browse/FFT1-86)은 P1 고객 추종 티켓이다. PR #20의 번호만 보고 배송 전체의 추적 키로 사용하지 않는다.

상태 모델은 조건이 충족됐다는 어댑터 이벤트를 소비한다. `SUCCEEDED`만으로 실제 정차나 하차를 추측하지 않는다.
복귀 경로의 Nav2→라인 경계가 확정되면 RETURN_NAV 아래에 라인 재획득 단계를 연결한다. 현재 모델만으로 H3/P1 복귀 경로가 구현됐다고 보지 않는다.
취소·실패는 STOPPING → 실제 정지 확인 → CANCELED/FAULT. 적재 상태는 유지한다.
실패 후 무조건 IDLE로 되돌리거나 센서가 다시 보인다고 자동 재출발하지 않는다.

## 4. 좌표·마커·장애물

- 지도는 현재 `maps/airport_map.yaml`과 PGM을 기준 자료로 삼는다. 최신 공간과 일치하는지 실측한 뒤 최종 채택한다.
- `config/places.yaml`은 지도 YAML·이미지 SHA256과 `map` 프레임 정차 자세 `(x,y,yaw)`를 묶는다.
- 모든 좌표는 미측정 상태다. 임의 좌표를 넣지 않으며 `measured: true`와 유한한 pose가 없으면 거부한다.
- 목표는 마커 중심이 아니라 로봇 중심의 정차 위치다. marker ID만으로 지도 좌표가 생기지 않는다.
- Gate 1–3의 마커는 8–10, 대기 P1–3은 1–3, P7은 7, 입국장은 27이다. [배정표](../../../../docs/aruco/README.md)를 따른다.
- Nav2는 센서 관측을 costmap에 반영해 우회/정지하도록 구성하고 검증한다. 보행자 이동 예측을 구현했다고 표현하지 않는다.
- 막힌 경로·센서 지연·AMCL 불확실·통신 단절을 구분해 보고하고, 재출발 정책은 관제 계약으로 결정한다.
- TS-3는 높이 11.5cm 모형이 라이다에 보이지 않는다고 기록했다. 라이다 높이 이상의 기둥 보강 제안이 있으나 실제 감지는 실측한다. 지도/알고리즘 튜닝으로 센서 사각을 해결했다고 보지 않는다.

라인 경로 또는 관제 계약이 늦으면 해당 통합 단계는 지연으로 기록하고, 그동안 모의 입력으로 로봇 측 실패 처리를 검증한다. 모의 통과를 팀 통합 완료로 보고하지 않는다.

## 8. 현장에서 확정할 항목

- 상차장 P7/대기 P1–3 중 실제 할당, 라인 입출구와 복귀 경계.
- 배송 목적지 ARR/게이트 및 각 정차 자세, 지도 최종 버전.
- 상차/팔 복귀/하차/복귀 허가 이벤트와 command/task/execution 식별자.
- AMCL 준비·정지·통신 단절·재개 판정의 수치와 담당 계층.
- 마커는 장소 확인만 필요한지, 정밀 정렬까지 필요한지 및 허용 오차.

미확정 값은 코드 기본값으로 만들어 실기에서 적용하지 않는다. 현재 패키지에는 자동 주행 entrypoint나 실기 launch가 없다.
